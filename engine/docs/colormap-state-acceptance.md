# Colormap state and release acceptance

Three campaign041 exacts connect actual current/hardware setters to the shared palette installer backend. Signed device-count gates, prior pointer stores, equal/null cases and retained callback mutations use guarded844-byte colormap storage. The palette remains an embedded address anchor.

The actual op_rd_colormap_free wrapper now replaces the extended-colormap fixture stand-in. Existing free observations move to the external free-entry backend; a separate scoped root-release observer verifies exact original-pointer/order and balanced calls at every reset. Existing count contraction/expansion during cleanup and slot snapshots are retained. Legacy opaque identity handles remain safe because neither the new wrapper nor the authored free-entry observer dereferences them; real free-entry integration must supply full typed storage before field access. Direct wrapper cases already use guarded844-byte roots.

The full shared checkpoint includes prior material and palette fixtures. No changed symbol/address, byte exclusion, padding or whole-executable claim is introduced.
