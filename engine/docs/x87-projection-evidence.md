# Transform and projection kernel

Reference: the pinned retail WMAIN.EXE in target.json, observed through Ghydra
on 2026-09-12. Function 0x0040EFD0, original analysis name FUN_0040efd0.
Observed behavior confidence: HIGH. Exact original source text: unknown.

## Source form and exact comparison

The reconstruction uses a normal C function with an inline x87 kernel. VC5 RTM
generates the frame, count-zero guard, callee-save handling, return, and alignment.
The kernel retains the observed register-resident constants and floating-point
stack operations. There are no original byte arrays, emit directives, naked
function frame replacements, copied binary fragments, or post-build patches.

The unusual duplicated ESI/EDI saves, explicit x87 condition-bit tests, retained
three-value floating-point stack across vertices, and integer test of float bits
are consistent with an original inline-assembly kernel. That source-history
interpretation remains inference. Our ordinary VC5 C wrapper plus reconstructed
assembly reproduces the whole observed section; it does not recover the original
comments, identifiers, formatting, or exact source boundaries.

The body ends at 0x0040F167: 407 instruction bytes. Ghidra confirms nine NOP
alignment bytes before 0x0040F170. All 416 bytes are compared. Eleven DIR32
address operands (44 bytes) are resolved only after their symbol and original
PE relocation are verified. The other 372 bytes include the full padding.
The resolved span SHA-256 is:
6bef3c49b782032d61b7e8d37d33e0d26dcae671e64c332d7f4e970b3b04e3e3.

This is function-section equality after address resolution, not verified retail

## Inputs, outputs, and observed data

The six cdecl arguments are vertex triples, output four-float slots, optional
signed selection indices, optional byte clip-code slots, signed count, and a
twelve-float affine matrix. Eight incoming references include mesh submission,
sprite rendering, particle rendering, polylines, and linked sphere effects.

The matrix is column-major: each output coordinate is accumulated from three
products in X/Y/Z order, then a translation. Each camera-space coordinate is
stored as float before projection. Camera-space Y is depth. The screen formulas
are centerX + X * (focal / Y) and centerY - Z * (focal / Y). Output Z becomes
reciprocal depth, and output W is its scaled mapping.

The center bit patterns at 0x005B8E5C and 0x005B5FE8 are loaded as floats. The
existing names op_width_bits/op_height_bits describe raw transfers only; do not
treat these cells as integer pixel widths when projecting. Focal is 0x005B6438.
The four viewport bounds, near bound, reciprocal-depth scale, and depth-mode
selector are listed as symbolic bindings in target.json. The mode selector is
0x00866FC8; mode 16 stores scaled reciprocal depth, other values store one minus
that value. No far-plane flag is generated by this routine.

## Edge cases that must survive reconstruction

- Count zero returns before dereferencing argument pointers or loading globals.
  Other negative counts enter one iteration. The final signed DEC/JG also stops
  after one slot for INT_MIN because of the CPU overflow condition.
- Without selections, triples are consumed sequentially. With selections, a
  positive index is one-based. A zero selection leaves output and clip slots
  unchanged but still advances their positions. Invalid nonzero indices have no
  bounds checks and remain caller obligations.
- Optional clip output performs no clip writes when null. For positive depth,
  bits 1/2 mean left/right, 8/4 mean top/bottom, and 16 means before near.
  Boundary equality stays inside. Nonpositive ordered depth yields 0x80.
- The depth-zero branch compares saved integer bits, not float equality.
  Positive zero takes the special path; negative zero takes reciprocal division,
  producing negative infinity under the masked default exception configuration.
- The reciprocal is stored to output Z without popping its x87 value. Depth W
  uses the retained precision. Under 53-bit round-to-nearest, depth 3 and scale
  10 produce Z bits 0x3EAAAAAB and W bits 0x40555555 in mode 16. Reloading rounded
  Z before multiplication would produce a different W.
- The clip tests use individual x87 condition bits. A quiet NaN can enter the
  plane tests and set 0x19; replacing them with modern ordered comparisons would
  change behavior.
- The x87 stack is balanced on all tested branches. The routine assumes enough
  caller-provided stack capacity and inherits the caller's FP control word.
  Tests explicitly select masked exceptions, 53-bit precision, nearest rounding,
  then restore the control word.

Synthetic tests in tests/projection_behavior.h cover these cases plus sparse and
duplicate indices, ordinary projection, both depth modes, exact clip boundaries,
matrix summation order, and unchanged skipped slots. The original executable is
read statically, never executed by these tests.

## Compiler advisory C4725

Microsoft documents [C4725](https://learn.microsoft.com/en-us/cpp/error-messages/compiler-warnings/compiler-warning-level-4-c4725?view=msvc-170)
as a level-four advisory about inline division instructions on defective early
Pentium processors. Private VC5 probes showed that the two divide instructions
compile under /W4, fail under /W4 /WX, and compile under /W4 /WX when only C4725
is disabled. In this wibo profile VC5 did not print the advisory text; the failed
exit codes still prevented acceptance. A minimal non-dividing asm probe passed.

The candidate therefore scopes disable:4725 to this function and restores the
level four afterward. The waiver is explicit in target.json and registry.json and
travels into every new verification record. source_policy.py rejects other,
missing, unbalanced, or unrecorded diagnostic directives. /W4 /WX remains active
for all other diagnostics. This is a compiler-diagnostic waiver, not permission
to ignore comparison bytes or claim compatibility with defective Pentium CPUs.

Additional compiler probes verify the waiver boundary. VC5 accepted the kernel
with warning(4:4725) after its body, rejected another dividing function after
that restoration, and rejected a separate C4101 unused-variable warning. A fresh
unwaived compiler invocation also rejected the division advisory. The older
warning(default:4725) spelling did not restore the level-four advisory in this
profile, so the accepted source uses explicit warning(4:4725). The policy tests
reject a regression to the ineffective default spelling.
