# Sprite release acceptance

Canonical `op_release_sprite` at 0x004295f4 connects to shields, halos, ripple materials and zap shutdown. It returns0 without a resource callback for a NULL slot or NULL handle; otherwise it passes the captured resource to the resource manager, clears the live pointer slot after that callback, and returns1. Its complete 71-byte span and one operand must match. All shared declarations use the recovered int return; existing callers ignore it.

A single authored `op_release_resource` dispatcher replaces the former sprite-release stand-in. Focused tests cover nulls, current/other slot mutations and a slot pointing to itself. Connected halo fixtures use explicit visit schedules and separate owner visits from resource callbacks. They predict silent NULL-handle owner/count stores, callback-time owner clears, later-slot activation/clearing, current-handle replacement clearing, and no revisit of an earlier slot. Shutdown also tests aliased handles in three distinct slots. Zap covers absent and present cached handles. Shield texture observes the cleared old handle before acquisition; shield load starts with absent resources and therefore has no release backend call. Ripple checks nonnull resource order and callback mutations without claiming access to the caller's private local slots.

All expectations use authored owned data. External resource-manager behavior remains a fixture boundary; this does not establish a whole retail executable. No byte exclusions or warning waivers are permitted. Historical focused evidence remains unchanged.
